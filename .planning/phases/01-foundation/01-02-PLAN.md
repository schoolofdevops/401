      4. `APILatencyP99` — `"StateValue": "INSUFFICIENT_DATA"` (realistic edge case — new metric with not enough data)

      4. State change OK -> ALARM at 10:05 (recurrence)
      5. Action triggered at 10:05
      6. Configuration change (threshold lowered from 90 to 85) at 08:00 (earlier that day — context for why it's alerting more)
    - Each item: AlarmName, AlarmType "MetricAlarm", HistoryItemType ("StateUpdate" or "Action" or "ConfigurationUpdate"), HistorySummary (human-readable), HistoryData (JSON string with oldState/newState), Timestamp (ISO 8601)
