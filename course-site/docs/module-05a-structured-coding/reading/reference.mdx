# Reference: Structured AI Coding

Quick reference material for the 5-phase structured workflow, context model, and validation tooling used in Module 5a.

---

## 1. 5-Phase Workflow Quick Reference

| Phase | Input | Output | Validation |
|-------|-------|--------|------------|
| **1. Brainstorm** | Goal or gap description | List of missing components, clarifying questions | Compare against your manual gap analysis |
| **2. Design** | 4-layer context block (Task/Role/System/Procedure) | Architecture document — files, API versions, purposes | Verify all files and constraints are included |
| **3. Blueprint** | "Skeletons only" instruction | YAML scaffolds with `spec: {}` | Check apiVersions, naming conventions, label structure |
| **4. Implement** | Exact production values | Fully populated YAML/HCL manifests | Visual inspection before validation tools |
| **5. Validate** | Generated manifests | Lint/dry-run results, fixes applied | All validation tools pass, deploy to staging |

## 2. 4-Layer Context Model Applied to IaC

The context model from Module 1 applied to infrastructure generation tasks:

### Helm Chart Generation (Track A)

| Layer | What to Include | Example |
|-------|----------------|---------|
| **Task** | Exact output — files, kinds, purpose | "Add HPA, PDB, ServiceMonitor, NOTES.txt to the reference-app Helm chart" |
| **Role** | Expertise frame + responsibilities | "I am an SRE building production Kubernetes infrastructure on a KIND cluster" |
| **System** | Kubernetes version, operators, services, ports, label conventions | "KIND cluster, Kubernetes 1.32, kube-prometheus-stack in monitoring namespace, services: api-gateway:8080, catalog:8081, worker:8082, ServiceMonitor requires release: prometheus" |
| **Procedure** | Constraints, validation requirements, naming rules | "Use Helm 3 template syntax; stable APIs only; use `{{ include "reference-app.fullname" . }}` for all names; minReplicas: 2, maxReplicas: 5 for HPA; minAvailable: 1 for PDB" |

### CI/CD Pipeline Generation (Track B)

| Layer | What to Include | Example |
|-------|----------------|---------|
| **Task** | Exact workflow additions — jobs, steps, triggers | "Add matrix testing, OIDC authentication, and a staging deploy job to the existing ci.yml" |
| **Role** | DevOps engineer responsibility + risk frame | "I am a DevOps engineer responsible for a production CI/CD pipeline. Changes must not break existing test jobs." |
| **System** | Repo structure, existing job names, runners, target environments | "GitHub Actions, ubuntu-latest runners, existing jobs: test (runs on push), services: api-gateway, catalog, worker, staging namespace: staging, prod namespace: app" |
| **Procedure** | Naming conventions, secret names, required permissions, OIDC role ARN | "Use actions/checkout@v4, docker/metadata-action@v5; OIDC role: arn:aws:iam::ACCOUNT:role/GithubActionsECR; secrets: ECR_REGISTRY; staging deploys on push to main, prod deploys on version tags" |

## 3. Common AI Errors in Helm Charts

These patterns appear frequently when insufficient context is provided. Use the Blueprint phase to catch most of them before full implementation.

| Error Pattern | What It Looks Like | Why It Happens | Fix |
|--------------|-------------------|----------------|-----|
| Deprecated apiVersion | `apiVersion: apps/v1beta1` | AI training data includes old tutorials | Specify `Kubernetes 1.32 stable APIs only` in System context |
| Missing unit suffix | `cpu: "500"` instead of `cpu: "500m"` | Statistical pattern from diverse examples | Provide exact values with units in Implement phase context |
| Hardcoded names | `name: my-app-hpa` instead of `{{ include "reference-app.fullname" . }}-hpa` | AI doesn't know your `_helpers.tpl` conventions | Reference `_helpers.tpl` naming convention in System context |
| Selector mismatch for ServiceMonitor | `matchLabels: app: reference-app` missing `release: prometheus` | Without kube-prometheus-stack knowledge, AI uses generic selectors | Include `release: prometheus` requirement in Procedure context |
| Hardcoded values that should be templated | `minReplicas: 2` instead of `{{ .Values.hpa.minReplicas \| default 2 }}` | AI generates for single use, not reusable charts | Specify "values.yaml-driven" or "templated" in Task context |
| Wrong namespace for CRDs | ServiceMonitor in app namespace, not monitoring namespace | Without explicit instruction, AI defaults to Release.Namespace | State namespace explicitly in System context |

## 4. Common AI Errors in CI/CD Pipelines

| Error Pattern | What It Looks Like | Why It Happens | Fix |
|--------------|-------------------|----------------|-----|
| Deprecated actions | `actions/checkout@v2` | AI training data includes older workflow examples | Specify action versions in Procedure context: `actions/checkout@v4` |
| Missing permissions block | No `permissions:` in jobs using OIDC | Without OIDC context, AI uses static credentials pattern | Include full OIDC permissions in System context |
| Wrong secret names | `${{ secrets.AWS_SECRET_ACCESS_KEY }}` | AI defaults to common names without knowing your naming convention | List exact secret names in Procedure context |
| Matrix not exhaustive | Tests only one Go/Node version | Without knowing your multi-version requirement, AI generates minimal matrix | Specify target versions in Task context |
| Missing `if:` conditions for prod | Staging and prod jobs both trigger on push | AI generates symmetric jobs; prod guard requires explicit constraint | State deploy trigger conditions in Procedure: "prod on tag, staging on main" |
| No `job summary` step | No `$GITHUB_STEP_SUMMARY` output | AI doesn't know your observability preference | Include job summary requirement in Task or Procedure context |

## 5. Validation Command Cheat Sheet

### Helm

```bash
# Lint the entire chart — catches template syntax and values issues
helm lint reference-app/helm/reference-app/

# Render all templates to stdout — visual inspection
helm template reference-app reference-app/helm/reference-app/ \
  --namespace app | less

# Validate rendered manifests against Kubernetes API (no apply)
helm template reference-app reference-app/helm/reference-app/ \
  --namespace app | kubectl apply --dry-run=client -f -

# Test upgrade path (important before applying to existing cluster)
helm upgrade --dry-run reference-app reference-app/helm/reference-app/ \
  --namespace app
```

### GitHub Actions

```bash
# Lint workflow files — catches YAML and Actions-specific issues
# Install: go install github.com/rhysd/actionlint/cmd/actionlint@latest
actionlint .github/workflows/ci.yml

# Check YAML structure independently
yamllint .github/workflows/ci.yml
```

### Kubernetes Manifests (standalone)

```bash
# Dry-run a single manifest
kubectl apply --dry-run=client -f monitoring/alerting-rules.yaml

# Dry-run with server-side validation (catches CRD schema issues)
kubectl apply --dry-run=server -f monitoring/alerting-rules.yaml

# Validate against a specific namespace
kubectl apply --dry-run=client -f monitoring/ -n monitoring
```

## 6. Gap Analysis Template

Use this at Step 0 (before touching AI) and in Phase 1 (Brainstorm) context:

```
## Baseline
- What exists: [list current resources and capabilities]
- Chart version: [helm version, kubernetes version]
- Existing templates: [list template files]

## Production Gap Analysis
- Missing reliability: [e.g., HPA — no autoscaling on load]
- Missing availability: [e.g., PDB — no minimum availability guarantee]
- Missing observability: [e.g., ServiceMonitor — Prometheus cannot scrape]
- Missing operational tooling: [e.g., NOTES.txt — no post-install guidance]

## Environment Constraints
- Kubernetes version: [e.g., 1.32]
- Operators deployed: [e.g., kube-prometheus-stack v65.3.1 in monitoring namespace]
- Label requirements: [e.g., ServiceMonitor requires release: prometheus]
- Naming convention: [e.g., {{ include "reference-app.fullname" . }}-{component}]
```
