# Environment Setup

This guide covers everything you need to install before the course. It is organized in two phases:

- **Day 1 Setup** — Docker, Kubernetes tools, an AI coding tool, and the reference app. Required before Module 1.
- **Day 2–3 Setup (Hermes)** — The Hermes agent framework. Required before Module 7. Install this after Day 1.

**Estimated time:**
- Day 1 Setup: 30–45 minutes
- Hermes Setup: 10–15 minutes

:::info Workshop vs Self-Paced
**Workshop participants:** Your instructor will tell you which steps to complete before Day 1. Complete Day 1 Setup before arriving. Hermes Setup will be done as a group at the start of Day 2.

**Udemy learners:** Work through both phases before starting Module 7. Complete Day 1 Setup before Module 1, then return here for Hermes Setup before Module 7.
:::

## Day 1 Setup

### Step 1: Docker

All Kubernetes labs run containers locally. Docker is the required container runtime.

**Install Docker Desktop** from [docker.com/get-started](https://www.docker.com/get-started/). Docker Desktop includes the Docker daemon, CLI, and Docker Compose.

> **macOS ARM (Apple Silicon):** Download the Apple Silicon installer, not the Intel one.

**Allocate enough resources.** Open Docker Desktop → Settings → Resources:
- **CPUs:** 4+
- **Memory:** 6 GB minimum (Prometheus + app services + PostgreSQL need ~4 GB combined)
- **Disk:** 30 GB minimum

**Verify:**

```bash
docker --version
# Expected: Docker version 26.x.x
```

> **Minimum version:** Docker 24 or later.

### Step 2: Kubernetes Tools

#### KIND (Kubernetes IN Docker)

KIND runs a complete Kubernetes cluster as Docker containers on your laptop. No cloud account required.

**macOS:**

```bash
brew install kind
```

**macOS (direct binary, if not using Homebrew):**

```bash

# Intel
```

### Step 6: Deploy the Reference Application

The reference application is a microservices system that serves as the lab environment for Modules 1–6. It includes:
- Three Rust backend services (api-gateway, catalog, worker)
- A Svelte health dashboard
- PostgreSQL database
- Prometheus + Grafana for observability

**Deploy:**

```bash
cd reference-app
make deploy
```

**What this does:**
1. Creates a KIND cluster named `lab`
2. Installs PostgreSQL via Helm
3. Installs Prometheus + Grafana (kube-prometheus-stack)
4. Builds and deploys the three Rust services and dashboard

**Expected time:** 5–10 minutes on first run (Docker image pulls).

**Expected output:**

```

Installing PostgreSQL...
Installing Prometheus stack...
Deploying reference app...

Deployment complete!
Dashboard: http://localhost:30080
Grafana:   http://localhost:30090 (admin/admin)
```

**Verify:** Open [http://localhost:30080](http://localhost:30080). You should see the health dashboard showing `api-gateway`, `catalog`, and `worker`, all green.

### Step 5: Lab Wrapper Aliases (One-Time Setup)

From Module 7 onwards, the labs use course-shipped mock wrappers at
`infrastructure/wrappers/` that intercept `kubectl`, `aws`, and `psql` calls when
`HERMES_LAB_MODE=mock`. These wrappers serve deterministic fixture data for the
six Kubernetes failure scenarios, mock AWS responses, and mock psql outputs —
letting you run the labs offline without a real cluster, AWS account, or database.

#### Why this setup is needed

Hermes spawns its terminal tool as `bash -lic` (login + interactive). Login-shell
startup reads system and user startup files that **rebuild PATH** — on macOS via
`/usr/libexec/path_helper`, and on most systems via whatever conda/cargo/rancher/etc.
added to your `~/.bash_profile`. The net effect: any wrapper directory you prepend
to `PATH` in your outer shell gets demoted inside Hermes's subshell, and `kubectl`
resolves to the real binary instead of the mock wrapper.

The clean, portable fix is to use **bash aliases** in `~/.bash_profile` instead
of relying on `PATH` prepending. Aliases:

- Are preserved through login-shell startup (define them with
  `shopt -s expand_aliases` enabled)
- Are expanded by bash's parser at command-execution time, even in `bash -c`
  invocations (which is what Hermes runs)
- Leave your global `PATH` untouched, so real `kubectl`/`aws`/`psql` remain
  accessible via absolute path or `\kubectl` (backslash bypass)

:::important Which shell does this apply to?
Regardless of your interactive terminal shell (bash, zsh, fish), Hermes always
spawns `bash -lic` for tool execution. That means:

- The alias block goes in **`~/.bash_profile`** (what bash reads during login
  startup) — NOT `~/.zshrc`, `~/.bashrc`, or `config.fish`
- Your login shell being zsh is irrelevant; Hermes invokes bash as a child process
- If you don't have a `~/.bash_profile`, create an empty one first: `touch ~/.bash_profile`
:::

---

#### Setup for macOS and Linux (including WSL2)

**Step 1: Add the alias block to `~/.bash_profile`**

Copy this whole block into your terminal and run it once:

```bash
cat >> ~/.bash_profile <<'EOF'

# ── Hermes DevOps Course lab wrapper aliases ─────────────────────────────
# When HERMES_LAB_WRAPPERS is set before launching `hermes chat`, route
# kubectl/aws/psql through the course's mock wrappers. Needed because
# Hermes spawns `bash -lic`, which triggers login-shell startup that
# rebuilds PATH and demotes any wrapper dir we set in PATH.
if [ -n "${HERMES_LAB_WRAPPERS:-}" ] && [ -d "$HERMES_LAB_WRAPPERS" ]; then
  shopt -s expand_aliases
  alias kubectl="$HERMES_LAB_WRAPPERS/mock-kubectl"
  alias aws="$HERMES_LAB_WRAPPERS/mock-aws"
  alias psql="$HERMES_LAB_WRAPPERS/mock-psql"
fi
# ─────────────────────────────────────────────────────────────────────────
EOF
```

**Step 2: Per-session export before launching `hermes chat`**

Every time you start a lab session, from your course root directory:

```bash
cd /path/to/course
export HERMES_LAB_WRAPPERS="$(pwd)/infrastructure/wrappers"
export HERMES_LAB_MODE=mock
export MOCK_DATA_DIR="$(pwd)/infrastructure/mock-data"
hermes -p track-c chat
```

`HERMES_LAB_WRAPPERS` is inherited by Hermes's bash subshell. When that subshell
reads `~/.bash_profile`, the alias block kicks in and defines `kubectl`/`aws`/`psql`
aliases pointing at the wrapper scripts.

---

#### Setup for Windows

On Windows, you have two supported bash environments:

##### Option A: WSL2 (recommended)

WSL2 gives you a full Linux bash environment, which behaves identically to the
macOS/Linux setup above. Follow the macOS/Linux instructions inside your WSL2
distribution (Ubuntu, etc.).

**Path note:** Inside WSL2, your course directory might live at a Linux path
like `/home/<user>/course` or at a Windows-mounted path like
`/mnt/c/Users/<user>/course`. Either works — `$(pwd)` will produce the correct
absolute path when you `cd` into the course root first.

Install Hermes inside WSL2 (not on Windows host) so the `bash -lic` subshell
is the same bash that reads your WSL2 `~/.bash_profile`.

##### Option B: Git Bash (MinGW)

Git Bash is the MSYS2 bash shipped with Git for Windows. It reads
`C:\Users\<user>\.bash_profile` (accessible as `~/.bash_profile` from within
Git Bash). Instructions are nearly identical:

**Step 1: Enable symlink support in git** (one-time, needed for the wrapper
`kubectl`/`aws`/`psql` symlinks that ship in the course repo):

```bash
git config --global core.symlinks true
```

Then re-clone the course (or run `git checkout -- infrastructure/wrappers`
inside an existing clone) so the symlinks get materialized.

**Step 2: Add the alias block to `~/.bash_profile`**

Open Git Bash and run:

```bash
cat >> ~/.bash_profile <<'EOF'

# ── Hermes DevOps Course lab wrapper aliases ─────────────────────────────
if [ -n "${HERMES_LAB_WRAPPERS:-}" ] && [ -d "$HERMES_LAB_WRAPPERS" ]; then
  shopt -s expand_aliases
  alias kubectl="$HERMES_LAB_WRAPPERS/mock-kubectl"
  alias aws="$HERMES_LAB_WRAPPERS/mock-aws"
  alias psql="$HERMES_LAB_WRAPPERS/mock-psql"
fi
# ─────────────────────────────────────────────────────────────────────────
EOF
```

**Step 3: Per-session export**

Git Bash represents Windows paths with forward slashes and a `/c/` prefix for
the C: drive:

```bash
cd /c/Users/<you>/path/to/course
export HERMES_LAB_WRAPPERS="$(pwd)/infrastructure/wrappers"
export HERMES_LAB_MODE=mock
export MOCK_DATA_DIR="$(pwd)/infrastructure/mock-data"
hermes -p track-c chat
```

**Step 4: Tell Hermes where Git Bash lives (if not auto-detected)**

Hermes looks for Git Bash on Windows automatically, but if it can't find it
you can point it explicitly:

```bash
export HERMES_GIT_BASH_PATH="/c/Program Files/Git/bin/bash.exe"
```

Add this to `~/.bash_profile` to make it permanent.

**Known Windows limitations:**
- KIND clusters on Windows require Docker Desktop with WSL2 backend (recommended)
  or Podman Desktop — they will not work with Git Bash alone
- Some lab steps that use `chmod`, `find -exec`, or Linux-only utilities may
  need WSL2 rather than Git Bash
- If you hit shell-level compatibility issues in Git Bash, switch to WSL2

## Troubleshooting

### Docker

**Docker not running:**
Start Docker Desktop, wait 30 seconds, then retry `bash setup/verify.sh`.

**Pods stuck in Pending:**
Docker Desktop may need more memory. Open Docker Desktop → Settings → Resources → increase Memory to 8 GB.

### KIND Cluster

**KIND cluster creation fails:**
```bash
kind delete cluster --name lab
cd reference-app && make deploy
```

**Dashboard not accessible at localhost:30080:**
```bash
kubectl get pods -n app --context kind-lab
```
All pods should show `Running`. If pods are in `Pending` or `CrashLoopBackOff`, check Docker resource allocation.

**Port 30080 already in use:**
```bash
lsof -i :30080
```
Find the process and stop it, or adjust the port in `infrastructure/kind/cluster-config.yaml`.

### Claude Code

**Claude Code authentication fails:**
- Update: `npm update -g @anthropic-ai/claude-code`
- Check [status.anthropic.com](https://status.anthropic.com)
- Use API key: `export ANTHROPIC_API_KEY=sk-ant-...`

**Node.js version too old:**
```bash
node --version  # must be v18 or later
brew install node   # macOS
# or: nvm install 18 && nvm use 18
```

### OpenCode

**OpenCode provider connection fails:**
- Re-copy your API key from the provider console
- Check the provider's status page for rate limit resets
- Try a different provider (e.g., switch from Gemini to Groq)

### Hermes

| Problem | Likely cause | Fix |
|---|---|---|
| `hermes: command not found` | Install location not in PATH | Add `~/.local/bin` to PATH and restart terminal |
| `hermes run "say: OK"` returns auth error | Provider login not completed | Re-run `hermes login --provider <your-provider>` |
| LLM connectivity fails | Wrong API key or expired token | Re-run `hermes login …` with a fresh key |
| Google AI Studio rate limit error | Free tier: 500 req/day | Wait until next UTC day or switch provider |
| HF Inference: model not found | Model name changed | Check [huggingface.co/models](https://huggingface.co/models) for current Llama-3.1-8B model ID |

### General

**`kind` or `kubectl` not found after installation:**
The binary may not be in your PATH. Check:
```bash
echo $PATH
```
Ensure `/usr/local/bin` is included. Add if missing: `export PATH="$PATH:/usr/local/bin"`.

## Windows Notes (WSL2)

All lab commands run inside WSL2.

1. Install WSL2 with Ubuntu 22.04+: open PowerShell as Administrator and run `wsl --install`
2. Install Docker Desktop for Windows with WSL2 integration enabled (Settings → Resources → WSL Integration → enable your Ubuntu distro)
3. Inside WSL2, install KIND, kubectl, and Helm using the Linux commands above
4. Claude Code and OpenCode both work natively in PowerShell or WSL2
5. All `bash setup/*.sh` scripts must be run from a WSL2 terminal

> **Why WSL2?** Lab shell scripts and the Makefile use bash. Windows PowerShell is not compatible with bash scripts.
