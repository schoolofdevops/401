# Reference: AI-Assisted IaC

Quick-reference tables and templates for Module 6 — AI-Assisted Infrastructure as Code.

---

## 1. Terraform Validation Cheat Sheet

| Command | What It Does | When to Run |
|---------|--------------|-------------|
| `terraform init` | Download providers, initialize backend, install modules | Once per project; again when providers change |
| `terraform fmt` | Format HCL files to canonical style | Before every commit |
| `terraform validate` | Check syntax + provider schema (no API calls) | After every AI generation step |
| `terraform plan` | Show what will be created/changed/destroyed | Before every `apply`; requires provider credentials |
| `terraform plan -out=tfplan` | Save plan to file for later apply | CI/CD pipelines; peer review workflows |
| `terraform apply tfplan` | Apply a previously saved plan | Ensures apply matches what was reviewed |
| `terraform test` | Run `.tftest.hcl` test files (Terraform 1.7+ required) | CI validation, mock_provider testing without credentials |
| `terraform show` | Display current state or a saved plan in human-readable form | Debugging; reviewing what was applied |
| `terraform state list` | List all resources in state | Before destructive operations |

**Key constraint:** `terraform validate` does NOT require AWS credentials or network access. It checks the HCL against the locally downloaded provider schema. Always run it immediately after AI generation.

**Version check:**
```bash
terraform version
# Must be >= 1.7.0 for terraform test with mock_provider
```

## 2. Kubernetes and Helm Validation Cheat Sheet

| Command | What It Does | When to Run |
|---------|--------------|-------------|
| `kubectl apply --dry-run=client -f manifest.yaml` | Validate YAML syntax and K8s schema locally (no cluster API call) | After every AI generation step |
| `kubectl apply --dry-run=server -f manifest.yaml` | Server-side schema validation (cluster API call, no actual change) | Pre-apply review; catches webhook validation errors |
| `kubectl diff -f manifest.yaml` | Show delta between current cluster state and the manifest | Pre-apply review; equivalent of `terraform plan` |
| `kubectl get applications -n argocd` | Show ArgoCD Application sync and health status | Monitor GitOps sync progress |
| `helm lint ./chart` | Check Helm chart templates for errors | After editing chart templates |
| `helm template ./chart` | Render chart to YAML without deploying | Preview what will be applied; pipe to `kubectl apply --dry-run` |
| `helm template ./chart \| kubectl apply --dry-run=client -f -` | Render + validate in one step | Full pre-deploy check without touching the cluster |
| `helm diff upgrade release ./chart` | Show delta between installed release and new chart (requires diff plugin) | Before `helm upgrade` |

**ArgoCD sync status meanings:**

| Sync Status | Health Status | Meaning |
|-------------|--------------|---------|
| Synced | Healthy | Cluster matches Git; all resources healthy |
| Synced | Progressing | Cluster matches Git; resources still starting up |
| OutOfSync | Healthy | Cluster has drifted from Git (manual change detected) |
| OutOfSync | Degraded | Cluster differs from Git AND resources are unhealthy |
| Unknown | Unknown | ArgoCD cannot reach the cluster or repo |

**ArgoCD Application CRD key fields:**

```yaml
spec:
  source:
    repoURL: https://github.com/USER/REPO  # Must be a Git URL, not local path
    targetRevision: HEAD                    # Branch, tag, or commit SHA
    path: relative/path/to/chart           # Path within the repo
  destination:
    server: https://kubernetes.default.svc # In-cluster reference
    namespace: app                          # Target namespace
  syncPolicy:
    automated:
      prune: true     # Delete cluster resources removed from Git
      selfHeal: true  # Revert manual changes that drift from Git
    syncOptions:
      - CreateNamespace=true  # Auto-create namespace if it does not exist
```

## 3. Common AI Errors in IaC

| Error Type | Example | How to Catch | Fix Strategy |
|------------|---------|--------------|--------------|
| **Schema drift** | `security_groups` instead of `vpc_security_group_ids` in `aws_instance` | `terraform validate` | Pin provider version in CLAUDE.md; include correct attribute names in generation prompt |
| **Hallucinated attribute** | `alarm_type = "threshold"` in `aws_cloudwatch_metric_alarm` | `terraform validate` | Provide the resource schema block as context; run validate immediately after generation |
| **Version mismatch** | Using `count` and `for_each` on the same resource | `terraform validate` | Specify Terraform version constraint in CLAUDE.md; `required_version = ">= 1.7"` |
| **Missing dependency** | Referencing SNS topic ARN as a hardcoded string instead of resource reference | `terraform plan` | Use resource references (`aws_sns_topic.alerts.arn`) not hardcoded ARNs; review plan graph |
| **Wrong namespace** | App deployed to `default` namespace instead of `app` | `kubectl apply --dry-run` | Specify namespace explicitly in CLAUDE.md; include `namespace:` in every resource metadata |
| **Local path in repoURL** | `repoURL: file:///Users/...` in ArgoCD Application | ArgoCD sync fails with "failed to get git client" | CLAUDE.md must state: "ArgoCD syncs from GitHub fork, not local filesystem" |
| **Missing selfHeal** | `syncPolicy.automated` without `selfHeal: true` | Manual inspection; test by making cluster change | Include `prune: true` and `selfHeal: true` in CLAUDE.md vocabulary section |

## 4. CLAUDE.md Template for Terraform Projects

Copy and customize this template when starting a new AI-assisted Terraform project.

```markdown
# Terraform Project — [Project Name]

## System State
- AWS region: [us-east-1 | us-west-2 | etc.]
- Target environment: [dev | staging | prod | lab]
- Terraform version: [1.7+ | 1.9+]
- AWS provider: hashicorp/aws >= [5.0 | 5.31]

## Constraints
- [Free tier ONLY | Production — no cost constraints]
- Instance types: [t2.micro for free tier | t3.medium for staging | m5.large for prod]
- [Basic CloudWatch monitoring (no detailed — costs extra)]
- [No resources that incur charges beyond free tier]
- Data source for AMI lookup — never hardcode AMI IDs (region-specific, change over time)

## Resource Naming Convention
- All resources: prefix with project name (e.g., "myapp-ec2-...")
- Tags required on all resources:
  - Name: descriptive name
  - Environment: [dev | staging | prod | lab]
  - [Owner: team or service name]
  - [CostCenter: billing code]

## Vocabulary (define your domain terms explicitly)
- "monitoring" = CloudWatch metric alarm on CPUUtilization
- "notification" = SNS topic + email subscription
- "module" = reusable Terraform module in modules/[name]/
- "alarm_actions" = list of SNS topic ARNs to notify when alarm fires

## Prohibited Patterns
- Do not hardcode AMI IDs — always use data "aws_ami" with most_recent = true
- Do not use count and for_each on the same resource
- Do not use deprecated attributes: security_groups (use vpc_security_group_ids)
- lifecycle blocks cannot reference variables
```

## 5. CLAUDE.md Template for GitOps Projects

Copy and customize this template when starting a new AI-assisted ArgoCD/GitOps project.

```markdown
# GitOps Project — [Project Name]

## System State
- Cluster: [context name, e.g., "kind-lab" or "prod-cluster"]
- Kubernetes version: [1.32 | 1.30 | etc.]
- ArgoCD version: [stable | 2.10+]
- Namespaces:
  - [app]: application workloads
  - [argocd]: ArgoCD control plane
  - [monitoring]: observability stack (if present)

## Constraints
- ArgoCD syncs from GitHub fork, not local filesystem (file:// paths will fail)
- [Local KIND cluster — no cloud resources | EKS cluster — IAM auth required]
- [Resource patches required for laptop constraints if KIND]

## Vocabulary (define your GitOps terms explicitly)
- "GitOps" = Git as single source of truth; ArgoCD continuously reconciles cluster state to match
- "sync" = ArgoCD detects drift between Git and cluster, applies changes automatically
- "Application CRD" = ArgoCD custom resource (apiVersion: argoproj.io/v1alpha1, kind: Application)
- "prune" = ArgoCD removes cluster resources that are no longer in Git
- "selfHeal" = ArgoCD reverts manual cluster changes that drift from Git
- "in-cluster" = server: https://kubernetes.default.svc (ArgoCD managing its own cluster)

## Required Application CRD Fields
- metadata.namespace: argocd (always)
- spec.source.repoURL: Git URL (not local path)
- spec.syncPolicy.automated.prune: true
- spec.syncPolicy.automated.selfHeal: true
- spec.syncPolicy.syncOptions: [CreateNamespace=true]

## Prohibited Patterns
- Do not use file:// or local paths in repoURL
- Do not omit syncPolicy.automated (manual sync only is not GitOps)
- Do not hardcode image tags in Application CRD (use chart values or Helm valueFiles)
```

## 6. Validation Workflow Reference

The recommended validation workflow for AI-generated IaC — run these commands after every generation step, not just at the end.

### Track A: Terraform

```bash
# After Step 2 (CLAUDE.md created, before generation):
# No commands — just verify CLAUDE.md exists and claude is reading it

# After Step 3 (main.tf generated):
terraform init                    # Download providers
terraform validate               # Check syntax + schema — fix errors before continuing
terraform fmt                    # Normalize formatting

# After Step 4 (variables.tf and outputs.tf generated):
terraform validate               # Re-check with all files present

# After Step 5 (full module complete):
terraform plan -input=false      # Full logic check (requires AWS credentials)
# OR
terraform test                   # Mock validation (requires Terraform 1.7+)
```

### Track B: ArgoCD/GitOps

```bash
# After Step 5 (Application CRD generated):
kubectl apply --dry-run=client -f argocd-app.yaml   # Validate YAML schema
kubectl diff -f argocd-app.yaml                      # Preview changes (requires cluster)

# After Step 6 (Application deployed):
kubectl get applications -n argocd                   # Check sync status
kubectl get pods -n app                              # Verify workloads running

# After Step 7 (GitOps demo):
watch kubectl get applications -n argocd             # Monitor sync in real-time
kubectl get pods -n app -l app.kubernetes.io/name=api-gateway  # Verify scale-up
```
